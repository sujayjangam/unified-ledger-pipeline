# Paid-by — plan

> **Status: planned 2026-11-15; PR 1 merged and deployed 2026-11-15 (#97); PR 2, the button, not started.** Step 2 of group-trip splitting in `ROADMAP.md`.
> Names below are fictional.

## Goal

Record who paid each entry, separately from who logged it and which account paid. One payer per
entry, stored as a person, so step 4 (`/balances`) reads one column. Travel minimum only: it must
ship well before the deploy freeze.

## Decided (2026-11-15)

Spliit and SplitPro both store the payer as a person on the expense, apart from the account and
from who added it; neither records a payment method (their schemas, read 2026-11-15). This plan
follows that data model, and keeps the OpenAI call out of choosing the payer.

1. **Python reads the payer from the message** (first). "paid by Carol" or "Carol paid" is matched
   against known names in tested Python, the way "last week" is read
   ([ADR-0031](../../decisions/0031-last-week-from-message-text.md)). The model never decides the
   payer, so "split with Carol" can't become "Carol paid".
2. **A "Paid by" button on the card** (fallback). It opens a list of people to tap, to fix what
   Python found or set what it missed.
3. **Stored as a column:** `transactions.paid_by_participant_id`.
4. **An outside payer's entry goes on one shared account, "Paid by someone else"**, with no owner.
5. **An explicit household flag**, `participants.is_household`. Totals skip entries whose payer
   is outside the household.

## The payer and the account must agree

The rules, in order (Alice sends; Bob is household; Carol is outside it):

1. **YouTrip top-up:** unchanged. The funding card pays, and its owner is the payer.
2. **The text names an outside payer:** the account is "Paid by someone else", whatever account
   the model picked, Cash included. How an outside person paid isn't recorded (decision 1), and
   this keeps the model's account pick out of an outside payer's entry. If the model picked a
   household-owned account, the card warns.
3. **The text names a household payer, or none:** the account is chosen as today. Then an owned
   account decides the payer. An unowned one (Cash, the wallet) takes the text payer, or the
   sender. With no account named, a household text payer gets their own default, not the
   sender's; the foreign-currency fallback to the wallet still comes first.

| Message | Account | Payer | Rule |
|---|---|---|---|
| "Lunch 40 on my Visa" | Alice's Visa | Alice | 3: owner |
| "Lunch 40 on Bob's Visa" | Bob's Visa | Bob | 3: owner |
| "Bob paid 40 on his Visa" | Bob's Visa | Bob | 3: text and owner agree |
| "Bob paid 40 cash" | Cash | Bob | 3: unowned, text decides |
| "Bob paid 40" | Bob's default | Bob | 3: payer's default |
| "Lunch 40" | Alice's default | Alice | 3: as today |
| "Lunch 40 AUD" | wallet | Alice | 3: currency fallback, sender |
| "Bob paid 40 AUD" | wallet | Bob | 3: currency fallback, text payer |
| "Bob paid 40 on Alice's Visa" | Alice's Visa | Alice | 3: owner wins; the card warns |
| "Carol paid 40" | Paid by someone else | Carol | 2 |
| "Carol paid 40 cash" | Paid by someone else | Carol | 2 |
| "Carol paid 40 AUD" | Paid by someone else | Carol | 2 |
| "Carol paid 40 on my Visa" | Paid by someone else | Carol | 2; the card warns |

A warning line never blocks a save. The "Paid by" button applies the same rules to a tapped
payer: an outside payer moves the entry to "Paid by someone else". A household payer keeps an
unowned account or one they own, and otherwise moves to their default.

**A name that doesn't match.** Voice is the main input, and Whisper can misspell a name. When the
text has "paid by …" or "… paid" but no candidate matches, the card shows "⚠️ Couldn't tell who
paid" and the payer falls back as in rule 3. It is never silent.

**A failed trip read.** The candidates fall back to household participants, so "Carol paid"
won't match. The card already shows the trip-read warning, and the unmatched-name warning above
shows too.

Every row of the table, each button move and both warnings are unit tests.

## Design

**Migration 0007** (hand-written, additive):
- `participants.is_household BOOLEAN NOT NULL DEFAULT false`, then
  `UPDATE participants SET is_household = true WHERE telegram_user_id IS NOT NULL`, then a
  check that anyone with a `telegram_user_id` is household (only household members use the bot).
  The update comes before the check, so it can be added, and household entries never drop out
  of totals.
- `transactions.paid_by_participant_id BIGINT NULL`, FK → `participants.id`. NULL on old rows
  and on CLI or REST API rows means "not recorded": read it as the account's owner, or the sender
  for an unowned account, as today. Every new bot entry sets it.

**Seed file.** Participants gain `"household": true`. The seed script only inserts rows and
fills empty columns today, so it gains one guarded update that sets the flag on an existing row
(never clears it). The "Paid by someone else" account is a
row in the seed file like any other, with no owner. Its name is a constant in
`app/services/participants.py`, like `WALLET_NAME`. If an outside payer is found and that account
doesn't exist, the entry is refused, the same as `WalletNotSetUp`: never guess.

**Reading the payer (Python).** A new function in `app/services/participants.py`, called from
`process_expense_text` (never a handler). It matches whole-word "paid by <name>" and
"<name> paid" / "<name> pays" against the candidates: the sender's trip members when trip mode
is on, otherwise household participants. "I paid" / "paid by me" is the sender. No match → no
text payer. Today's per-message trip read (`load_active_trip`) returns only the trip, so it
gains the members, read in the same database block (one more query, not a new block: about one
round trip, by the menu-speed numbers in `ROADMAP.md`).

**`resolve_payment`** takes the text payer and applies the table above, setting `account_id` and
`paid_by_participant_id` together. "Paid by someone else" is left out of
`directory.account_names()` itself (no second list), so the model can't pick it; only Python's
rule puts an entry there.

**The card** shows a "Paid by: <name>" line and a "Paid by" button. The list of people (ids,
names, household flag, default account) is copied onto the pending entry, so a tap never loads
the directory. Callback data stays under Telegram's 64-byte limit. The button menu is built so
step 3's "Add split" menu can reuse it.

**Totals.** `get_period_summary` and `get_category_summary` in `app/services/ledger_queries.py`
skip a row whose payer is set and not household. `get_recent_entries` and
`find_recent_duplicate` keep every row.

## Risks to test

- Python misses a phrasing ("Carol covered dinner", voice transcripts). The card shows "Paid by:
  Alice", and the button fixes it. Add phrasings only when real messages miss.
- A name that is also an everyday word. Display names are the match list, so check the real
  trip names for clashes before the trip.
- Until splits exist (step 3), a shared bill a household member paid still counts in full in
  the totals.

## Steps

Two PRs (decided 2026-11-15). **PR 1:** the migration, the column, the household flag, Python
reading the payer, the rules, the card line, the warnings and the totals filter: steps 1–5 and
7–11, without the button. **PR 2:** the "Paid by" button and its menu (step 6), built so step 3's
"Add split" menu can reuse it.

1. ADR: the payer is a person column, read by Python from the text, with a button to fix it; an
   owned account decides the payer.
2. Migration 0007 on a Neon branch; `docs/SCHEMA.md` updated.
3. `is_household` and the new account constant in `participants.py`; seed script validation and
   insert.
4. Payer reading function, with unit tests for each phrasing and for "split with Carol" (no
   payer).
5. `resolve_payment` and the table above, with unit tests.
6. Card line, "Paid by" button and menu, pending-entry copy, save. Tests with stubbed Telegram
   objects.
7. Totals filter in `ledger_queries.py`.
8. `python -m scripts.check_extraction` (the account list changes). Gate: `pytest`,
   `ruff check .`, import check.
9. Test bot on the Neon branch with a fictional trip-sized directory.
10. Production: backup, `alembic upgrade head` by hand, seed the household flags and the new
    account, then merge.
11. README, ROADMAP and CLAUDE.md check.

## Out of scope

How an outside person paid (card or cash), more than one payer per entry, filling in the payer
on old rows, splits (step 3).
